# JSONC on Android

The Android JSONC host is `AndroidJsoncScreen` in `android-bridge`. It parses a
view from the application's assets and creates Megalodonte components. The
Android bridge renders those components with native Android widgets and Canvas;
it does not use WebView or JavaFX. The desktop `megalodonte-jsonc-ui` renderer is
not packaged into the APK because it depends on JavaFX.

## Component coverage

Every `type` in `megalodonte-jsonc-ui/schema/view.schema.json` has an Android
renderer. This is component coverage, not complete desktop property parity.

| JSONC type | Android behavior |
| --- | --- |
| `Column`, `Row`, `Container` | Megalodonte linear layouts; padding, spacing, dimensions, background color and fill |
| `Text` | Native text, `style.fontSize`, static text or state binding with display formatting |
| `Button` | Native button; `events.onClick` or `props.action` invokes a Java handler; height and fill width supported |
| `Input`, `PasswordInput`, `TextArea` | Native text inputs; string state binding, placeholder, width/height, enter event and supported display formats |
| `Scroll` | Native vertical scroll host containing one child |
| `Select` | Native spinner with string or `{value,label}` options |
| `DatePicker` | Native date dialog; selected value is ISO `yyyy-MM-dd` |
| `Image`, `ImagePreview` | Native image view sourced from app assets or local files |
| `ImageSequence` | Horizontally scrollable image strip with selected index |
| `SoundSequence` | Selectable list of sound segments with start, duration and volume |
| `DataList` | Native selectable list with label, detail and badge |
| `DiffView` | Read-only monospace text with selectable content |
| `Table` | Horizontally scrollable native rows and columns, including image columns, row selection, multiple selection and double-click action |
| `BarChart`, `PieChart` | Native Canvas chart driven by `{label,value}` items |
| `Slot` | Named Megalodonte component provided by Java before render |

String, boolean, integer and decimal state declarations are accepted. The
renderer currently binds string states to text, inputs, media and data sources;
integer states hold list selection. A Java action updates a string state with
`screen.setState(name, value)`. Use `screen.slot(name, component)` before
`MegalodonteApp.run` to fill a `Slot`.

`Text` and `Input` support `format.kind` values `mask`, `currency`, `number`,
`uppercase` and `lowercase` where applicable. Mask and currency inputs store
digits while displaying punctuation. Password inputs reject formatting.
An action handler can read a bound string input through
`screen.getStringState("fieldName")`; use `screen.setState("fieldName", value)`
to update it. This supports form logic in Java while the view remains JSONC.

```jsonc
{
  "version": 1,
  "id": "home",
  "states": { "message": { "type": "string", "initial": "" } },
  "view": { "type": "Column", "children": [
    { "type": "Button", "props": { "text": "Start" },
      "events": { "onClick": "start" } },
    { "type": "Text", "bind": { "text": "message" } }
  ] }
}
```

```java
AndroidJsoncScreen screen = new AndroidJsoncScreen(jsonc);
screen.onAction(action -> {
    if ("start".equals(action)) screen.setState("message", "Ready");
});
MegalodonteApp.run(context -> context.useView(screen));
```

## Assets and current differences from desktop

Store images under `app/src/main/assets/`. Image `source` can refer to an asset
(for example `images/logo.png`) or to a local absolute/file URI. Remote image
URLs are not loaded on the UI thread. `ImageSequence` and `SoundSequence` are
selection controls; `SoundSequence` does not play audio, matching the desktop
sequence editor's selection role.

Android currently implements the primary component behavior, but several
desktop-specific features are not yet equivalent: arbitrary CSS/theme style
properties, JSONC validation rules, table pagination,
advanced chart labels/legends,
and dynamic slot replacement after mount. The Android backend's broader API
matrix is in [COMPATIBILITY.md](COMPATIBILITY.md). Unsupported component types
throw an exception; properties without Android handling should be treated as
unsupported until listed here.

## Build and validation

Generate both projects using `megalodonte --platform android --mode native`
and `--mode jsonc`, then run `./gradlew :app:assembleDebug :app:lintDebug
:app:check`. These checks compile the bridge and verify the Android runtime
dependency graph. Launching and interacting with the generated APK requires
an Android 15 device or emulator.

On 2026-10-20, an APK generated by `megalodonte-cli --platform android
--mode jsonc` was installed on the local API 35 emulator with all 21 schema
types in one view. It launched without crashing; a button action updated bound
text, table rows and both chart types rendered, and vertical scrolling reached
the final pie chart. This is a smoke test, not full behavioral coverage of
every property.

Run `python3 scripts/check_jsonc_coverage.py` from the Android backend checkout
to compare the JSONC schema's component enum with the Android renderer's dispatch
cases. This detects newly added schema types that lack an Android implementation;
it does not replace device interaction tests.
